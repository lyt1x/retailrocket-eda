# 📊 Retailrocket EDA

Исследовательский анализ событий интернет-магазина: поиск категорий, которые покупают хуже среднего, и этапа воронки, на котором теряются покупки

## ⭐ Key Findings

- 160 из 1086 категорий покупают значимо хуже среднего по магазину, 176 лучше, 750 на уровне среднего
- Красные категории дают 45% просмотров, но около 23% покупок: недобор составляет около 4900 покупок (22% от покупок с известной категорией)
- В 11 из 15 самых проблемных категорий покупатели теряются после корзины, в 4 до неё
- 80% просмотров приходится на 227 категорий, поэтому приоритизировать стоит крупные
- Конверсия зависит от времени суток: около 0,4% с 8 до 13 UTC и около 0,9% с 16 до 22

## ⚙️ Technical Overview

1. Из `item_properties` берётся последняя известная категория товара, события склеиваются с ней
2. По каждой категории считаются просмотры, добавления в корзину и покупки
3. Ожидаемое число покупок: `просмотры * средняя конверсия магазина`, недобор: ожидаемое минус фактическое
4. По z-оценке категория помечается красной (ниже -2), зелёной (выше 2) или жёлтой
5. Красные категории ранжируются по недобору, для каждой определяется слабый этап: до или после корзины
6. Результат проверяется на сверхактивных посетителей

## ⚠️ Limitations

- В логе нет сессий, поэтому доли посетителей описательные, а не строгая воронка
- Используется последняя известная категория товара, у 9% событий категории нет
- Цены анонимизированы: низкая конверсия не всегда проблема, результат это список для проверки

## 🛠️ Installation

Клонируйте репозиторий

```
git clone https://github.com/lyt1x/retailrocket-eda.git
cd retailrocket-eda
```

Установите зависимости

```
pip install -r requirements.txt
```

Скачайте [датасет с Kaggle](https://www.kaggle.com/retailrocket/ecommerce-dataset), распакуйте и положите все файлы в папку `data/`

Откройте `eda.ipynb` и запустите все ячейки

## 📦 Used Technologies

- `numpy` - расчёт z-оценки
- `matplotlib` - графики
